# PRD: Карточная раскладка списка средств

Status: ready-for-agent

## Problem Statement

На мобильном телефоне при размере шрифта выше среднего у таблицы средств появляется горизонтальный скролл. Пользователь не может увидеть все данные строки одновременно без прокрутки вбок. Особенно проблемно поле «счёт» — названия могут быть длинными («Депозит в синем банке на 3 года под 18%») и не влезают в узкую колонку таблицы.

## Solution

Заменить табличное отображение списка средств на карточную раскладку с использованием shadcn `Card`. Каждая строка holding становится отдельной компактной карточкой, где данные расположены вертикально — сумма сверху, название счёта снизу на всю ширину с переносом. Горизонтальный скролл исключён при любых разрешениях и размерах шрифта.

Единый лейаут на всех устройствах — один столбец карточек. Итоговая сумма выделена в отдельную карточку с muted-фоном.

## User Stories

1. Как пользователь мобильного телефона, я хочу видеть сумму каждого средства в его валюте без горизонтального скролла, чтобы быстро оценить состояние портфеля.
2. Как пользователь с длинными названиями счетов, я хочу видеть полное название счёта без обрезки, чтобы не путать похожие счета.
3. Как пользователь, я хочу видеть конвертированную сумму в итоговой валюте под основной суммой, чтобы понимать вклад каждого средства в итог.
4. Как пользователь, я хочу видеть иконку источника данных (биржи) рядом с каждой суммой, чтобы знать, откуда взят курс.
5. Как пользователь, я хочу быстро редактировать средство — кнопка редактирования должна быть видна всегда, без захода в меню.
6. Как пользователь, я хочу управлять средством (переместить, включить/исключить из итога, удалить) через компактное меню-кебаб.
7. Как пользователь, я хочу видеть общий итог всех средств в выбранной валюте, визуально отделённый от списка.
8. Как пользователь, я хочу видеть средства, исключённые из итога, полупрозрачными — так же, как сейчас.
9. Как пользователь десктопа, я хочу тот же карточный интерфейс, что и на мобильном — единообразный опыт.
10. Как пользователь, я хочу видеть тултип с курсом конверсии при наведении на сумму, чтобы понимать, по какому курсу считается конверт.
11. Как пользователь без добавленных средств, я хочу видеть понятное сообщение «Нет сохранённых средств» с подсказкой, как добавить.
12. Как пользователь, я хочу видеть единый интерфейс на всех устройствах — не должно быть разных лейаутов для десктопа и мобильного.

## Implementation Decisions

1. **Единая карточная раскладка.** Таблица `<Table>` полностью заменяется на список shadcn `Card`. Лейаут один для всех разрешений, без брейкпоинтов.

2. **Структура holding-карточки.** shadcn `Card` с `size="sm"`:
   - `CardHeader` с `CardTitle` (иконка источника + сумма в валюте счёта) и `CardAction` (кнопка редактирования + кебаб-меню).
   - `CardContent` — конвертированная сумма (`≈ X Y`) и название счёта без обрезки. Конверт показывается, только если валюта счёта не совпадает с итоговой.

3. **Внешняя карточка «Мои средства».** Без изменений в структуре: `Card` → `CardHeader` (заголовок + кнопка «Добавить») → `CardContent` со списком holding-карточек и итоговой карточкой в конце. `CardFooter` не используется — итог встроен в поток карточек.

4. **Итоговая карточка.** Отдельный `Card` с `size="sm"` и `bg-muted/50`. Содержит сумму итога и `TotalCurrencyPicker`.

5. **Действия.** Единый лейаут без разделения на мобильный/десктоп: кнопка редактирования [✏️] всегда видна в `CardAction`, остальные действия (переместить, скрыть/показать, удалить) — в кебаб-меню [⋮].

6. **Disabled-состояние.** Карточка `opacity-40`, как текущие строки таблицы. Тултип с курсом остаётся.

7. **Пустое состояние.** Без изменений — текст внутри внешнего `Card`.

8. **Чистые функции выносятся в `lib/`:**
   - `computeTotalAmount(holdings, conversionRates) → number` — сумма enabled holding'ов.
   - `computeConverted(amount, rate) → string | undefined` — конвертированная сумма.
   - `isSameCurrency(ticker, totalTicker) → boolean` — совпадает ли валюта с итоговой.

9. **Удаляемые модули:** `HoldingsTable`, `HoldingRow` (логика мигрирует в карточные компоненты).

10. **Модифицируемые модули:** `HoldingsCard` (замена таблицы на карточки), `HoldingRowActions` (унификация Mobile/Desktop).

11. **Новые модули:** `HoldingCardItem`, `HoldingsTotalCard`.

## Testing Decisions

Только unit-тесты. Чистые функции тестируются в изоляции, UI-компоненты не тестируются.

- **Что делает тест хорошим:** тестирует внешнее поведение функции (вход → выход), не зависит от реализации, покрывает граничные случаи (NaN, undefined, пустой массив).
- **Тестируемые функции:**
  - `computeTotalAmount` — корректная сумма только enabled holding'ов с валидным rate, пропуск undefined/NaN rate, пустой массив.
  - `computeConverted` — корректный расчёт, возврат undefined при NaN/undefined rate.
- **Приоритет:** `computeTotalAmount` и `computeConverted` содержат бизнес-логику расчёта итога, их некорректная работа напрямую влияет на пользователя.

## Out of Scope

- Изменение структуры данных Holding или Ticker.
- Изменение логики работы с курсами и конверсией.
- Изменение диалогов добавления/редактирования средства.
- Интеграционные тесты.
- Вёрстка в несколько колонок на десктопе.
- Новый функционал, не связанный с отображением списка средств.
